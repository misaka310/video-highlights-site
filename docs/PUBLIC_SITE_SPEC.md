# Public Site Specification

## 1. 文書の位置づけ

この文書は `dotitao moments` 公開サイトの製品仕様の正本である。

- 公開UIの実装正本: `frontend/`
- 再生挙動の詳細: `docs/PLAYBACK_SPEC.md`
- 公開データの詳細: `docs/data-contract.md`
- 配信用生成物: `public/`

実装とこの文書が食い違う場合、意図的な仕様変更として承認されたものを除き、この文書へ合わせる。

## 2. サイトの目的

YouTubeライブアーカイブのコメント量から抽出した見どころを、利用者が短時間で選び、該当時刻からすぐ再生できる非公式ファンサイトを提供する。

公開UIはYouTube providerだけを表示・選択する。provider専用の切替タブは追加せず、YouTube VODの日付タブから選択したデータを再生する。旧Twitchキャッシュが入力へ残っていても、公開一覧・ページャー・VODタブには出さない。

公開画面では、内部Whisper文字起こしや内部解析過程ではなく、次を表示する。

- VOD
- 見どころ見出し
- 見どころサムネイル
- 見どころ開始時刻
- 短いタグ
- コメント量の盛り上がりマップ
- YouTube公開字幕の再生同期表示
- 配信概要
- 更新情報

## 3. 技術構成

- React
- TypeScript
- Vite
- Cloudflare Kumo
- YouTube IFrame Player API
- YouTubeの公開埋め込み再生

公開UIの対応provider:

- YouTube via YouTube IFrame Player API

内部互換テストだけで保持するprovider:

- Twitch via Twitch SDK / iframe fallback

YouTube live_chatはOracle VM上で取得し、ローカルの直接取得を公開パイプラインの成功経路として扱わない。取得したvideoOffsetTimeMsecはcontent_offset_secondsへ正規化し、コメント本文や投稿者情報は保存しない。

ローカルURLは `http://localhost:4174/` とする。

`frontend/` が公開UIの唯一の正本であり、表示内容・並び順・再生挙動の実装と検証はfrontendのコードとテストへ集約する。

## 4. ページ構成

ページは次の順序と領域を持つ。

### 4.1 ヘッダー

左側:

- サイトアイコン
- サイト名 `dotitao moments` または設定されたサイト名
- `直近2ヶ月の配信の見どころをすぐ再生［非公式ファンサイト］`

右側:

- データ更新日時
- 次回更新予定日時
- `site.feedback_url` が設定されている場合だけ `要望・誤り報告はこちら` の外部リンク

日時は日本時間で表示する。

### 4.2 PCメイン領域

PCでは2カラム構成とする。

左カラム:

1. provider対応プレイヤー
2. プレイヤー内の再生同期文字起こし
3. 盛り上がりマップ

右カラム:

1. VOD日付タブ
2. 選択中VODの「見どころ / あのさ」切替タブ（初期表示は見どころ3件）
3. `この配信について`
4. ページャー

プレイヤーだけを大きくして右カラムを圧迫しない。左右を一画面として調整する。

### 4.3 スマートフォン領域

900px以下では1カラムとし、再生領域の後にVOD・見どころ・概要・ページャーを配置する。

- 横スクロールを発生させない。
- モバイルでは縦スクロールを許容する。
- プレイヤー、盛り上がりマップ、見どころカードの順序を崩さない。
- プレイヤー上または下へ、選択中の配信タイトルを重複追加しない。

## 5. PCレイアウトの受入条件

基準表示は `1792 x 864` とする。

この表示では次をすべて満たす。

- ページ全体の縦スクロールが発生しない。
- 横スクロールが発生しない。
- ヘッダー、プレイヤー、盛り上がりマップ、見どころ3件、配信概要、ページャーが一画面に収まる。
- プレイヤー表示幅は950px以上を目安とする。
- 右カラム幅は380px以上420px以下を目安とする。
- プレイヤー本体とbody直下のポータル領域の位置・幅・高さが一致する。

画面幅が広い場合でも、プレイヤーの16:9比率によって高さが増えすぎないよう、ページ全体の最大幅を制限する。

## 6. 視覚仕様

### 6.1 全体

- 青黒、暗いネイビーを基調とする。
- 紫はブランド、選択状態、グラフ線など必要なアクセントへ限定する。
- グレーの大きな面が周囲から浮かないようにする。
- 過剰なグラデーション、発光、強い影を追加しない。
- Kumoの既存部品の質感を保つ。

### 6.2 プレイヤー・マップ・右カラム

次を揃える。

- 背景の明度
- 境界線の強さ
- 角丸
- 部品間の余白
- ホバー時の変化量

盛り上がりマップは別部品に見せず、プレイヤーと同じ再生領域の一部として見せる。

### 6.3 再生同期文字起こし

- YouTube VODに公開字幕がある場合だけ、動画の下の再生補助エリアへ「前 / 今 / 次」を表示する。PCでは盛り上がりマップと横並び、狭い画面では縦並びにし、動画そのものには字幕パネルを重ねない。
- cue時刻は同じYouTube動画の再生秒を基準とし、旧Twitchとのoffset補正は行わない。
- 字幕取得失敗や字幕なしはVOD更新の失敗条件にしない。字幕がない場合はパネル自体を表示しない。
- 字幕全文はVOD本体JSONへ埋め込まず、選択中VODの `data/captions/{vod_id}.json` だけを遅延取得する。
- 文字起こしパネルは従来どおり、選択中VODの公開字幕cue全体を再生位置に同期して「前 / 今 / 次」へ表示する。「あのさ」抽出のために字幕表示を置き換えたり絞り込んだりしない。
- 内部Whisper文字起こしや見出し生成用テキストは公開しない。

### 6.4 右カラムの「あのさ」タブ

- VOD日付タブの下に「見どころ / あのさ」の切替タブを置く。初期選択は「見どころ」とする。
- 「見どころ」では従来どおり見どころ3件を表示し、既存カードの仕様・件数を変更しない。
- 「あのさ」では同じVODの公開字幕から、各項目が必ず「あのさ」で始まり文末まで復元できた発話だけを表示する。未完の断片や長い時間差をまたいだ別発話は結合しない。
- 「あのさ」の項目を選択すると、その発話開始時刻へ同一VOD内seekする。
- 「あのさ」一覧は右カラム内でスクロールさせ、PC基準表示でページ全体の縦スクロールを増やさない。

### 6.5 見どころカード

- サムネイルと見出しが主情報。
- 区間サムネイルがない場合は、VOD全体のサムネイルを表示する。
- 時刻をサムネイル上に表示する。
- タグは最大2件。
- 選択中カードは紫の境界・アクセントを使うが、背景全面を派手にしない。
- 見出しは最大2行を基本とする。

## 7. VOD・見どころ表示仕様

### 7.1 ページング

- 1ページにつきVODを5件表示する。
- `page` クエリでページを保持する。
- ページ移動時は初期再生方針へ戻し、自動再生しない。
- ページャーは総件数と現在範囲を表示する。

### 7.2 VOD順序

VODは `published_at` の新しい順に表示する。入力JSONの配列順へ依存しない。

公開対象はYouTube VODだけとする。旧Twitchデータが入力JSONや内部キャッシュに残っていても、表示件数・ページャー総件数・日付タブへ含めない。

### 7.3 見どころ順序

見どころは次の優先順位で並べ、先頭3件を表示する。

1. `rank`
2. `rank` がない場合は `start_sec`

### 7.4 見出し

- `headline` があれば使用する。
- YouTubeの `headline` が欠損している場合は見出し未生成として扱い、反応理由を見出しに昇格させない。
- 旧Twitchデータは公開対象外とし、公開UIでは`reason`を見出しへフォールバックしない。

## 8. 配信概要

`この配信について` には次の6項目をこの順序で表示する。

1. 配信タイトル
2. 配信日時
3. 長さ
4. チャット量
5. 再生状態
6. 再生位置

表示規則:

- タイトル欠損: `―`
- 日時欠損・不正: `―`
- 長さ: `HH:MM:SS`
- `duration_sec` がなければ `activity_map.duration_sec` を使う。
- それもなければ見どころの最大 `end_sec` を使う。
- 長さを解決できなければ `―`
- チャット量は `{合計}件 / 時間あたり約{件数}件`
- 合計または時間あたり件数が欠損・不正なら `―`
- 再生位置は `HH:MM:SS`

ラベルは `長さ` とし、`配信の長さ` へ変更しない。

## 9. 盛り上がりマップ

### 9.1 描画

- PC最大320点
- スマホ最大120点
- PC移動平均半径2
- スマホ移動平均半径3
- 点数を減らす場合は、区間内の最大値を残す。
- PC高さ88px
- スマホ高さ60px

### 9.2 表示要素

- コメント量の面グラフ
- 再生済み範囲
- 選択中見どころ範囲
- コメント未取得の末尾領域
- 現在位置線

`last_comment_sec = 0` は有効値であり、欠損扱いにしない。この場合は全末尾領域を未取得として表示する。

### 9.3 操作

- マップクリックで該当時刻へ移動し、音声付きで再生する。
- 現在位置表示はプレイヤーの実再生位置へ追従する。
- `10秒戻る` は実再生位置を優先する。

## 10. 再生仕様

詳細な状態遷移は `docs/PLAYBACK_SPEC.md` を正本とする。最低限、次を維持する。

- 初期表示では自動再生しない。
- 初期状態はミュート。
- 見どころ、VODタブ、盛り上がりマップのユーザー操作では音声付き再生。
- 同一VOD内はプレイヤーを作り直さずseekする。
- 別VODでは必要な場合だけプレイヤーを再生成する。
- 連続クリック時は最後の要求を優先する。
- 10秒戻るは実再生位置を基準にする。
- YouTube IFrame Player API取得失敗時はエラーをUIへ表示し、別providerへ切り替えない。
- iframeを重複生成しない。
- React上のプレイヤー枠とbody直下ポータルの寸法を一致させる。

## 11. ファビコンとメタ情報

- ファビコンの正本は `frontend/public/favicon.svg`。
- Vite開発サーバーはpublic directoryから `/favicon.svg` を返す。
- Vite buildは同ファイルを生成済みbundleへ含め、`scripts/build_public.sh` はbundle全体を `public/` へ配置する。
- `frontend/index.html` は `/favicon.svg` を参照する。
- ページタイトル、description、OGタイトル、OG descriptionはサイト設定へ追従する。
- ローカル環境ではアクセス解析を送信しない。

## 12. データとプライバシー

公開画面と公開生成物に、次を追加しない。

- コメント本文
- 投稿者情報
- 内部Whisper文字起こし本文
- 内部プロンプト
- モデル応答
- raw chat

YouTube自身が公開している字幕cueは、再生同期表示のため `data/captions/{vod_id}.json` に限って公開してよい。内部Whisper文字起こしは公開しない。

ただし、次の内部処理は公開UIから見えなくてもリポジトリ内に維持する。

- Groqによる見出し生成
- Whisperを利用する内部エンリッチメント
- 見出し前処理・評価・検証
- 公開データ生成処理

## 13. ビルド仕様

`scripts/build_public.sh` は次を行う。

1. `frontend/` のTypeScriptビルド
2. Vite本番バンドル生成
3. `public/` の再作成
4. 公開可能なVOD JSONのコピー
5. YouTube公開字幕JSONのコピー
6. 見どころサムネイルのコピー
7. サイト設定の出力
8. faviconのコピー
9. robots.txtとsitemap.xmlの生成

`public/` は生成物であり、公開UIの直接編集先にしない。

## 14. 変更禁止事項

明示的な仕様変更がない限り、次を行わない。

- プレイヤー下への配信タイトル追加
- 見どころ表示件数の変更
- VODページサイズの変更
- 盛り上がりマップの描画方式変更
- データ構造変更
- Groq、Whisper、内部エンリッチメントの削除
- 関係のない大規模リファクタ
- 公開サイトへのデプロイ
- push、PR、merge

## 15. 検証仕様

### 15.1 通常のフロント変更

```text
cd frontend
npx tsc -b --pretty false
npx eslint .
npx playwright test
```

### 15.2 PCのみのレイアウト調整

ユーザーのスマートフォン利用中ブラウザを再読み込みしない。PCのみの変更では次を使う。

```text
cd frontend
npx playwright test --project=desktop
```

基準viewportは `1792 x 864` とし、次を自動検証する。

- 2カラム
- プレイヤー幅
- 右カラム幅
- 横スクロールなし
- 縦スクロールなし
- 初期再生方針
- 同一VOD seek
- 別VOD切替
- last-click-wins
- 10秒戻る
- faviconのMIME type

### 15.3 スマホ検証

スマホ検証が必要な場合も、利用者の実端末や開いているブラウザを操作しない。独立したヘッドレスPlaywrightのmobile projectを使う。

### 15.4 公開生成物へ影響する場合

```text
bash scripts/build_public.sh
```

公開生成物を含む標準検証は、個別コマンドではなく次の正本を実行する。

```text
npm run verify
```

## 16. 仕様変更の手順

仕様を変える場合は次を同じ作業で更新する。

1. この文書
2. 関連する実装
3. 回帰テスト
4. 必要なら `docs/PLAYBACK_SPEC.md` または `docs/data-contract.md`

見た目だけを変更したつもりでも、寸法、表示順、欠損時表示、再生経路が変わっていないか確認する。
